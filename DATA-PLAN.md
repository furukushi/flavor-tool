## Long-term data behavior
- **Refresh policy**: No scheduled refresh. Data changes only through user actions in the app and through the Muse-side 1-minute sweep calling the queue actions (listQueuedJobs → startJob → applyJobResult / failJob) which the parent agent installs outside the app; the app itself embeds no Claude logic.
- **Growth**: Flavors, types, and generation history grow unbounded per spec (history has no cap and survives flavor deletion, shown by flavor name snapshot).
- **Ordering**: あいうえお順 = name string collation order (JS locale-independent code-unit sort approximating ひらがな→カタカナ→漢字→英数字), ties by created_at ascending. 使った順 = last_used_at descending, never-used last in あいうえお順. Folder mode groups by type master sort_order, multi-type flavors appear in each folder, untyped under 無分類. Jobs processed FIFO by created_at.
- **Time semantics**: All timestamps stored as epoch ms; last_used_at updates ONLY on successful clipboard copy (single-flavor copy). Job snapshots record values at enqueue time; consider_context is snapshotted per job from the app-wide setting (default ON).
